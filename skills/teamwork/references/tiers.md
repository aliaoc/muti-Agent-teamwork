# 任务分级（Small / Medium / Large）

## 判定信号

在 `00_intake/classification.md` 的 `signals` 里逐项写实（不要抄默认值）：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `files` | 整数 | 预计要改/要读的文件或模块数（粗略即可） |
| `external` | bool | 是否需要联网检索、外部资料或跑实验 |
| `verifiable` | bool | 验收标准能否用命令/文件核对（而非纯主观） |
| `parallel` | bool | 是否能拆成互不依赖的并行子任务 |
| `risk` | `low\|medium\|high` | 不可逆改动、对外发布、删除/覆盖数据等风险 |
| `user_demand` | bool | 用户是否明确要求多子 Agent / 分级 / 迭代 |

## 分级规则（满足 ≥2 条即取较高一级）

| 等级 | 典型特征 | 规划深度 | Worker 数 | 汇总方式 | 审核档 | 自动 N |
| --- | --- | --- | --- | --- | --- | --- |
| **Small** | 单文件/单问答；无外部检索；30 分钟内；可逆低风险 | 1 页：目标、3–5 步、验收清单 | 1–2 | 主 Agent 直接汇总 | quick：5–8 项检查 + 单维打分 | 1 |
| **Medium** | 2–5 个文件/模块；需检索、对比或小实验；有项目内验证命令 | 2–3 页：WBS、接口、风险、验收 | 3–4 | 主 Agent 直接汇总 | standard：6 维 rubric + 证据引用 | 2 |
| **Large** | 跨模块/跨系统；需外部资料或实验；验收多义；>2 小时；中高风险 | 详细方案：2–3 个备选、里程碑、依赖图、回滚 | 5–7 | 1 个全新 Final Agent | deep：6 维 + 证据抽查；审核人数按需 2+（先问用户） | 3 |

人数与上限：

- **计数口径**：下表及所有人数上限都按**单个任务（= 单个 run）**计算。同一对话/上下文里可以有多个任务，每个任务各自拥有自己的 Worker 集合、各自计数、互不占用名额；**禁止**把一个对话里多个任务的 Worker 相加去比 8。
- Worker 硬下限 1；S/M 复用为主，第 2 轮起原则上不再新建 Worker（新建会触发 warning）。
- **同一任务内累计 Worker 数**：Small ≤2、Medium ≤4、Large ≤7；L 级再 +1 个 Final Agent，合计上限 8。实际个数由主 Agent 按拆分决定，不机械取上限；跨轮复用同一 id 只算一个。
- 审核 Agent 数量不受 8 人上限约束（默认 1；当前实现 A–Z 支持 1–26 位），由迭代次数与任务要求决定，按单个任务计数；k>1 时先向用户说明成本并确认。


## 自动轮数（N=? 时）

`n = clamp(TIER_DEFAULT_N[tier] + n_adjust, 1, 10)`，`n_adjust ∈ {-1, 0, +1}`：

- +1：任务不确定性高、需要多轮打磨、第 1 轮预计只能出草稿；
- 0：按默认；
- -1：任务简单明确、用户赶时间。

必须写 `n_reason`（例如“验收标准主观，预计第 1 轮需按审核意见重来，+1”），并在聊天里播报最终轮数。

## 拆分与并行

- 拆分原则：每个 Worker 有**独立可验收**的产物路径；写作用域不重叠；单 Worker 工作量 ≈ 总工作量 / Worker 数。
- 有依赖的拆分（B 需要 A 的产物）→ `mode: staged`，并在 dispatch 的 worker 写 `dependencies`。
- deliverables 全放 `iterations/iter-NN/workers/wNN_artifacts/`；路径稳定、可复现。
- 不要为了凑人数拆无意义子任务；Small 允许 1 个 Worker 全包。

## 升级 / 降级

- 第 1 轮复核（GATE 或 REVIEW）后，如发现任务比预估复杂，主 Agent 可在 PLAN 阶段前 `set-tier Medium "理由"`（自动模式会同步默认 N）。
- `set-tier` 只允许在 INIT / CLASSIFY / PLAN 阶段；调整写入 history，不删旧文件。
- 降级仅当证据表明原分级明显过高（如实际 1 个文件、无需外部资料），并说明原因。

## 示例

- Small：把 `README.md` 的一段改写成安装说明并给 3 条验证命令。
- Medium：调研两个开源库并给出选型建议 + 最小可运行对比脚本 + 证据。
- Large：把某模块从 A 架构迁到 B 架构，含兼容层、回归测试、迁移文档与回滚步骤。
